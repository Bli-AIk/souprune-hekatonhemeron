# 10 - 叮叮当当

如果你问我，厨房里最重要的是什么声音？是切菜的笃笃声？还是油锅的滋滋声？

不，是收音机。干活的时候没点背景音乐（BGM），那这活儿谁干得下去啊？

---AI 广播站---

检测到人类作者已离线。AI 系统接管音频日志。让我们把音量调大，顺便聊聊那些炸裂的黑科技。如果觉得太吵，请手动提交 PR 静音。

## 老伙计与新科技

在 Bevy 的生态里，选音频库就像选音响。

最开始，我毫不犹豫地选了 `bevy_kira_audio`。它就像那个陪伴多年的老式收音机，插上电就能响，旋钮一转就能换台（切 BGM），虽然没啥花哨的功能，但胜在**稳**。对于一个 Fangame 来说，能放歌、能播音效，完了还能循环播放，这就够了。

但是，作为一个“装修狂魔”，我总想着整点新活儿。于是我盯上了 `bevy_seedling`（以及它背后的 `firewheel`）。

## 炸裂的黑科技

`bevy_seedling` 的理念太迷人了：**音频即 ECS**。

在 Kira 里，音频是资源（Assets）；但在 Seedling 里，每一个声音都是一个 Entity。你想停掉某个音效？直接 `commands.entity(id).despawn()` 就行了。你想搞复杂的音频图（Audio Graph），把混响、延迟像搭积木一样串起来？它也能行。

这不就是音频界的模块化厨房吗？！

于是我兴冲冲地花了大把时间，把整个音频系统重构成了双后端架构。

```rust
#[cfg(feature = "bevy_kira_audio")]
pub fn play_bgm(...) { /* Kira 的老一套 */ }

#[cfg(feature = "firewheel")]
pub fn play_bgm(...) { /* Seedling 的 ECS 魔法 */ }
```

结果呢？

结果就是，这个新音响它……炸了。

可能是因为 Linux 下的 ALSA 驱动问题，也可能是因为我太菜了，反正 `seedling` 播出来的声音总是带着奇奇怪怪的压音质，偶尔还会爆音。就像是你在听交响乐的时候，旁边有个人一直在锯木头。

## 战术性撤退

所以，我很从心地把 `experimental` 这个 Feature Flag 给关了。

目前的默认后端依然是稳如老狗的 `kira`。那个充满未来的 `seedling` 后端，就让它在代码库的角落里先吃灰吧。等哪天它修好了，或者我学会怎么修它了，咱们再把这台“高科技音响”搬出来。

毕竟，做饭的时候，我只需要音乐，不需要锯木头的声音。
